# Planning a project

**Pin down the goal**
- What does done look like? Write it as something you could check: "Site live at the domain, booking form sends an email".
- Who is it for, and by when?
- What is out of scope? Write that down too.

**Break it down**
- List the pieces. Each should be small enough to finish in one sitting and to know when it is finished.
- Put them in order. Note which ones block others.
- Find the riskiest or least understood piece and do it early.
- Find the smallest version that is useful on its own, and aim for that first.

**Estimate honestly**
- Give a range, not a single number. Things take longer than the best case.
- Flag anything that depends on someone else: content from a client, an approval, an account.

**Write the plan as**
1. Goal, in one sentence.
2. Not doing.
3. Steps in order, each with what done means.
4. Open questions and who can answer them.
5. The first thing to do right now.

**While working**
- Finish one step before starting the next.
- When something changes, update the plan instead of pushing on with a wrong one.

Keep it to one screen. Ask the user the questions you cannot answer yourself instead of assuming.
